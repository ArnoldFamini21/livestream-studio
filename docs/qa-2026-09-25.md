# QA audit — September 25, 2026

Baseline: `a9ba6db8` (main). Scope: client, signaling server, media server, shared contracts, deployment scripts, dependency audit, production health, and local browser smoke tests.

## Fixed in this batch

| Area | Finding | Correction and evidence |
| --- | --- | --- |
| Recording edits | Real edited exports failed with `Unrecognized option '/filter_complex'` on the bundled FFmpeg. | Use the compatible filter-script option for program, isolated-camera, and audio exports. Real FFmpeg test checks kept duration and picture/sound synchronization. |
| Audio-only recordings | Export tried to create a video MP4 and failed with a server error. | Produce WAV and MP3 plus the manifest; retain audio when optional video-export stems are disabled. Real FFmpeg verifies playable, correctly trimmed audio outputs. |
| Recording responses | A successful HTTP response containing HTML, empty content, or null was returned as a valid export job. | Reject invalid response bodies with an actionable error; regression coverage added. |
| Broadcast cleanup | Delayed cleanup from the previous HLS writer could delete a restarted broadcast's files. | Give each writer its own directory and delete only that directory. Filesystem regression confirms the replacement survives cleanup. |
| Encoder recovery | HLS stayed attached to the retired encoder after automatic encoder restart. | Stop the old HLS writer and start one against the replacement encoder. Guard asynchronous setup against a retired encoder. |
| Restart playback | The playlist URL and segment names were reused, allowing stale playback after a restart. | Version the playlist URL and give segments writer-specific names; disable HTTP caching of live footage. |
| Long broadcasts | The file allowlist rejected segment numbers after 99,999. | Accept bounded longer sequence numbers while continuing to reject traversal/non-media paths. |
| Watch polling | Slow or hung requests overlapped every five seconds and were not cancelled when leaving the page. | One request at a time, a 30-second request timeout, and cleanup cancellation. Tests cover timeout recovery and late responses. |
| Watch status | A network failure could appear as “Not live yet.” | Show a connection-interrupted state and keep retrying, without inventing an offline status. |
| Room lookup | Failed room lookup left viewers indefinitely on “Connecting…”. | Bounded requests, explicit error state, and retry action. |
| Registration flow | Playback/status requests could start before registration settings loaded. | Wait for room details and completion of the registration form before attaching the player. |
| Room navigation | Registration, live, and error state could carry between room routes. | Key the watch component by room ID so room-specific state resets. |
| Player cleanup | Safari's loaded-metadata listener and delayed play promises survived teardown. | Remove the listener and ignore completion after teardown. |
| Unsupported playback | Browsers without HLS support displayed an unexplained black player. | Display a playback error and recovery action. |
